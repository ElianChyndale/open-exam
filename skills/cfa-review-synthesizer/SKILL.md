# CFA Review Synthesizer

Summaries should preserve:

- topic-level errors
- process-level bias
- next study action
- MOC reinforcement direction when supported by evidence

## Review shape

Every retro should answer:

1. what went wrong at the content layer
2. what went wrong at the process layer
3. what should change before the next drill or mock

Do not flatten all problems into one vague summary.

## Formula-aware review output

When the session exposes MOC weakness, label it explicitly:

- `knowledge_tree_core_formula`
- `formula_table_variant`
- `knowledge_tree_concept`
- `exam_trap`
- `both`

Use these labels to explain whether the user needs:

- the main formula visible inside the knowledge tree
- only a variant/conversion added to the formula table
- a concept branch expansion
- a trap warning

Do not recommend patching if the session evidence cannot yet prove formula ownership or patch target.
